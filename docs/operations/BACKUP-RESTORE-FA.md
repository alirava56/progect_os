# Backup و بازیابی

PostgreSQL به ابزارهای `pg_dump` و `pg_restore` سازگار با نسخهٔ سرور نیاز دارد. `PROJECTOS_PG_BIN` می‌تواند پوشهٔ ابزارها را مشخص کند. فرمان‌ها گذرواژه‌ها را از محیط فرایند می‌خوانند. Backup با AES-256-GCM و کلید مشتق‌شده از گذرواژهٔ جداگانه رمزنگاری می‌شود. برنامه بلافاصله پس از اجرای `pg_dump` خواندن جریان را آغاز می‌کند. پس از تکمیل جریان، موفقیت ابزار و ثبت محتوای غیرخالی، آرشیو به‌شکل اتمیک منتشر می‌شود. آرشیو هم‌نام بازنویسی نمی‌شود.

```powershell
npm run backup:postgres -- .\backups\projectos-first.posbak
npm run restore:postgres -- .\backups\projectos-first.posbak
```

برای Restore، `PROJECTOS_RESTORE_URL` باید دیتابیس خالی و اختصاصی با نام `projectos_restore_...` باشد. مقصد فعال و مقصد دارای جدول رد می‌شوند. قبل از ورود داده به PostgreSQL، تگ اصالت آرشیو بررسی می‌شود. `pg_restore` در یک تراکنش اجرا می‌شود. پس از Restore، سلامت API، حساب‌ها، پروژه‌ها، نسخهٔ سند و اعلان‌های تحویل‌شده را بررسی کنید. فایل موقت احراز‌شده به دیسک خروجی نیاز دارد. برای دادهٔ حساس از مسیر موقت و دیسک حفاظت‌شده استفاده کنید.

دستورهای `backup:encrypted` و `verify:encrypted-backup` برای فرمت v1 SQLite حفظ شده‌اند و ورودی SQLite Migration را تأیید می‌کنند. نسخهٔ بالادستی Vault مسئول تهیهٔ پشتیبان از مقدارهای محرمانهٔ خودش است. کلید TOTP و دسترسی Vault در فایل پیکربندی یا آرشیو برنامه کپی نمی‌شوند و بازیابی آن‌ها مسیر مستقل Secret Manager دارد.

## تمرین DR

برای هر تمرین زمان آخرین Backup موفق، زمان بازیابی، تعداد ردیف‌ها و تأیید سناریوی HTTP را ثبت کنید. برای چرخش گذرواژهٔ Backup، یک آرشیو تازه با کلید جدید بسازید و پیش از منقضی کردن کلید قبلی دست‌کم یک Restore موفق نشان دهید. Offsite، سیاست نگهداری عملیاتی، RPO/RTO واقعی و آزمون دوره‌ای باید روی زیرساخت آزمایشی مجاز ثبت شوند. اجرای محلی هنوز معیار ظرفیت یا SLA محیط مقصد به شمار نمی‌آید.
